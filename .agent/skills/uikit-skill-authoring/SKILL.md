# 新增 Skill 的规范（新增时机判定 / SKILL.md 结构 / 格式约束 / 路由表登记）

> 命中本 skill 时，先说一句：**本次命中 skill: uikit-skill-authoring**。

## 触发词

- `新增 skill` / `加 skill` / `写 skill` / `补录 skill`
- `skill 规范` / `技能编写` / `技能文档` / `SKILL.md`
- `什么时候加 skill` / `要不要加 skill` / `有必要新增吗`
- `路由表` / `路由表登记` / `skill 路由`
- `skill 格式` / `skill 结构` / `skill 命名`

## 目标

`.agent/skills/` 下 skill 的公共契约：**什么时候有必要新增**、命名、段落结构、
Markdown 格式约束（IDE 检查器实证）、AGENTS.md 路由表登记。避免五类翻车：

1. 不读源码凭空写契约——写出来的「事实」与代码不符；
2. 为一次性改动建 skill——写完成本大于收益，路由表越来越臃肿；
3. 新 skill 结构与旧 skill 风格分裂，后续维护要猜；
4. 格式问题（fragment 代码带语言标注、裸星号、表格未对齐）触发 IDE 报错；
5. 忘记登记 AGENTS.md 路由表，skill 变死文件（永远不被路由命中）。

## 1. 什么时候有必要新增 skill（判定标准）

**新增前先过四道闸，全部通过才建：**

1. **高频/可预判反复**——该领域问题会反复出现：同类翻车已发生过（或按经验必然再踩），
   如「改公开 API 后 demo 的 vue-tsc 还在读旧类型」这类必踩坑；
2. **可沉淀为契约**——能从源码/配置提取**可验证**的事实（文件路径 + 行为），
   不是一次性决策或口味偏好；
3. **现有 skill 覆盖不到**——先查 AGENTS.md 路由表与现有 skill 的触发词/内容：
   **能扩展现有 skill（补触发词、加一节）就不新建**；边界重叠时互相引用；
4. **有反直觉点或硬约束**——行为与直觉不符（如 `t()` 不做插值、Provider 挂载后
   改 locale 不生效），值得写下来防再踩；纯顺理成章的事不需要 skill。

**否定情形（不新增）：**

- 一次性改动，做完即弃（如临时脚本、单次迁移）；
- 通用编程知识，非项目特定契约（Vue 语法、TS 基础不写）；
- 现有 skill 补几个触发词就能覆盖；
- 内容无法从代码验证——凭印象写的规范是毒药。

**标准流程**：全局扫描缺口 → 查根 `TECH-DEBT.md` 是否已登记（避免重复排查）→
按四道闸评估 → 读对应源码提取真实契约 → 确认触发词能命中 → 才动手写。

**粒度原则**：一个 skill = 一个领域契约；路由表已 20+ 行，新增要克制——
宁可扩展旧 skill，不轻易开新目录。

## 2. 命名与目录

- 目录：`.agent/skills/<name>/SKILL.md`（文件名固定 SKILL.md）；
- 命名：`uikit-` 前缀 + 领域 kebab-case（英文），如 `uikit-message-rendering`、
  `uikit-docs-authoring`；唯一例外 `websdk2-uikit-migration`（SDK 层历史名）；
- 标题：`# <中文一句话契约>（<关键点>）`，如 `# Vue3 UIKit 打包发布与构建契约（build / SDK 引入模式 / 产物结构）`；
- 路由表登记的 skill 名必须与目录名一致（路由表 → 文件路径一一对应）。

## 3. 段落结构（所有 skill 统一，按序）

1. `# 标题`——中文一句话契约 + 括号关键点；
2. `> 命中本 skill 时，先说一句：**本次命中 skill: <name>**。`——命中提示语，
   路由规则依赖它；
3. `## 触发词`——bullet 列表，覆盖口语（`改样式`、`加文案`）、术语（`unocss`、
   `i18n`）与文件/符号名（`useDemoSettings`、`chatConfig`）；
4. `## 目标`——先声明「避免哪几类翻车」，编号列表（1. 2. 3. …）；
5. 主体分节——`## 1. xxx` / `## 2. xxx`（或 `## 结构`），按域组织；写真实契约 +
   反直觉点，每节 bullet 粒度适中；
6. `## 硬规则 vs 软约定`——`**硬规则：**` / `**软约定：**` 两组 bullet
   （旧文件是 `## 硬规则（该拦的）` + `## 软约定` 分节，新写统一用合并式）；
7. `## 已知漂移（改到相关文件时注意）`——登记与 `TECH-DEBT.md` 的关联项；
8. `## 反面清单`——`- ❌ 行为——后果`，逐条对应「目标」里的翻车。

## 4. 内容契约

- 先读对应源码/配置提取真实契约，禁止凭印象写；每条断言要可验证
  （文件路径 + 行为）；
- 反直觉行为必须给证据：如「`t()` 不做插值」给出调用方 `.replace()` 的用法；
- 与已有 skill 边界重叠时互相引用（如 h5 相关 → `uikit-h5-adaptation`），
  不重复展开；
- 涉及技术债挂 `TECH-DEBT.md` 编号；引用代码位置用**文件路径而非行号**
  （随代码漂移）。

## 5. Markdown 格式约束（IDE 检查器实证，2026-08）

- **代码块语言标注**：标注会被 IDE 当对应语言解析——fragment 代码（数组/对象中间
  截断、`],` 结尾）必须**不带语言标注**（只写裸围栏），否则报 "Expression expected"；
  只有完整可解析语句（interface / 完整 const 声明）才允许带标注；
- **裸星号**：正文禁止出现裸 `*`（如 `enable*` 这类），用措辞替代
  （`enable 类开关`）或转义；`**`code`**`（加粗包行内代码）是合法写法，不受影响；
- **表格对齐**：列宽 = 显示宽度（CJK/全角 = 2，ASCII = 1），单元格**尾部补空格**，
  分隔行 `-` 数量与列宽一致；
- **触发时机**：表格检查只在文件被修改时触发全表检查——历史遗留未对齐表格
  （如 `uikit-cell-contract`）IDE 从不报，**不要顺手改**（扩大 diff）；
- **新表格行**：新增行各单元格显示宽度 ≤ 所在列现有列宽，否则需整表重排
  （AGENTS.md 路由表当前列宽：34 / 101 / 132 / 114）。

## 6. 路由表登记（AGENTS.md「Skill 路由表」）

- 新增 skill 后必须登记，否则路由匹配不到；
- 按主题就近插入，或放表格末尾；四列：Skill / 适用场景 / 触发词示例 / 文件；
- 文件列格式：`[.agent/skills/<name>/SKILL.md](.agent/skills/<name>/SKILL.md)`；
- 适用场景列写「能做什么」，触发词示例列写「什么话会命中」（与 SKILL.md 的
  触发词保持一致）；
- 登记后对照 §5 表格对齐规则自查新行（宽度 ≤ 现有列宽则无需整表重排）。

## 7. 验证（新增 skill 的门禁）

- 保存后在 IDE 问题面板确认无 markdown 报错（被修改的文件才触发表格全表检查）；
- 自查三件套：fragment 代码块无语言标注 / 正文无裸星号 / 表格按显示宽度对齐；
- 用「触发词」逐条模拟路由匹配，确认命中本 skill；
- 内容断言抽查：挑 2-3 条关键契约回源码验证，防止凭空写的错误沉淀。

## 硬规则 vs 软约定

**硬规则：**

- 新增 skill 必须走四道闸判定（§1），且先读源码提取契约。
- 新增后必须：按 §3 段落结构写 → 登记 AGENTS.md 路由表 → 过 §7 验证。
- fragment 代码块禁止带语言标注；正文禁止裸星号；表格按显示宽度对齐（CJK=2）。
- 命名必须 `uikit-` 前缀 + kebab-case；路由表名与目录名一致。
- 触发词必须覆盖口语表达，不能只有术语。

**软约定：**

- 标题 = 中文一句话契约 + 括号关键点。
- 已知漂移挂 TECH-DEBT 编号；引用代码位置用文件路径而非行号。
- 旧文件未对齐表格不顺手改，避免扩大 diff。
- 路由表已 20+ 行，新增要克制——能扩展旧 skill 就不开新目录。

## 已知漂移（改到相关文件时注意）

- §5 记录的是 2026-08 的 IDE markdown 检查器行为（dprint 风格）；IDE 升级后若
  检查规则变化，以实际报错为准更新 §5。
- AGENTS.md 路由表列宽（34 / 101 / 132 / 114）随最长单元格漂移，新增行前先量列宽。
- 本 skill 是元规范：它自身也必须遵守 §3-§7（自查先例）。

## 反面清单

- ❌ 不读源码凭印象写契约——写出来的「事实」就是错的。
- ❌ 为一次性改动建 skill——路由表臃肿，没人会再命中。
- ❌ 现有 skill 补两个触发词就能覆盖，却开新目录——碎片化。
- ❌ fragment 代码块带 ts 语言标注——IDE 报 Expression expected。
- ❌ 正文写裸 `*`（如 `enable*`）——IDE 报格式错误。
- ❌ 新表格行不对齐就提交——IDE 报 Replace X with Y。
- ❌ 忘记登记路由表——skill 永远不会被路由命中。
- ❌ 触发词只写术语——用户口语触发不了。
- ❌ 顺手对齐旧文件表格——扩大 diff，给审查制造噪音。
